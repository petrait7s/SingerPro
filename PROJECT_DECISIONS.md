# Project decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                    | Reason / implication                                                                                                                                                                                                                               |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Product identity "Singer Pro"; developer PETRA Software Solutions; supplied logo = PETRA logo                                                                                                                                                                                                                                                                                                               | Owner-confirmed. PETRA mark used subtly (About, login from P1, invoice footer from P3). No Singer/Beko marks.                                                                                                                                      |
| D2  | Stack: Tauri 2, React 19, TS 5.9, Vite 7, Tailwind 4, Rust, SQLite via SQLx 0.8, pnpm 10                                                                                                                                                                                                                                                                                                                    | Stable, mutually compatible. Latest majors (Tauri 3 alpha, TS 7, Vite 8) deliberately not used.                                                                                                                                                    |
| D3  | Rust split: `crates/core` (no Tauri) + `src-tauri` (thin command layer)                                                                                                                                                                                                                                                                                                                                     | Core fully testable on Linux without WebKit; enables a future server reuse.                                                                                                                                                                        |
| D4  | Money = `i64` paisa, `Money` newtype with checked ops                                                                                                                                                                                                                                                                                                                                                       | No floats. Display uses lakh/crore grouping (৳1,25,000.50). Percent rounds half away from zero.                                                                                                                                                    |
| D5  | IDs = UUIDv7 stored as TEXT                                                                                                                                                                                                                                                                                                                                                                                 | Time-ordered, portable to PostgreSQL `uuid`.                                                                                                                                                                                                       |
| D6  | Timestamps UTC RFC3339 TEXT; Dhaka (fixed UTC+6, no DST) for display and business-day boundaries                                                                                                                                                                                                                                                                                                            |                                                                                                                                                                                                                                                    |
| D7  | SQLite: WAL, `synchronous=FULL`, FK on every connection, busy_timeout 5s                                                                                                                                                                                                                                                                                                                                    | Durability over speed for financial data.                                                                                                                                                                                                          |
| D8  | `audit_logs` append-only via DB triggers; `actor_id` has no FK                                                                                                                                                                                                                                                                                                                                              | Audit must outlive users.                                                                                                                                                                                                                          |
| D9  | `branches` table with one default branch from P0                                                                                                                                                                                                                                                                                                                                                            | Multi-branch later is additive.                                                                                                                                                                                                                    |
| D10 | Document numbers via `document_sequences`, incremented in caller's transaction                                                                                                                                                                                                                                                                                                                              | Unique; rollback releases the number.                                                                                                                                                                                                              |
| D11 | Defaults seeded (never overwritten): tax disabled 0%, installment markup 0%, remainder to last installment, markup recognised proportionally to collections, no negative stock, returns need inspection                                                                                                                                                                                                     | All configurable settings; owner-approved where stated.                                                                                                                                                                                            |
| D12 | Tauri capabilities = `core:default` only; CSP self-only; no fs/shell/http plugins                                                                                                                                                                                                                                                                                                                           | Least privilege. Backup/restore (P1) will use narrow custom commands.                                                                                                                                                                              |
| D13 | Non-built modules show an honest "scheduled for Pn" page, not fake data                                                                                                                                                                                                                                                                                                                                     | No dead controls / mock KPIs.                                                                                                                                                                                                                      |
| D14 | Windows build runs on `windows-latest`; Linux job does lint/test                                                                                                                                                                                                                                                                                                                                            | Installer is unsigned until a certificate is supplied (SmartScreen warning expected).                                                                                                                                                              |
| D15 | First-run setup creates the Owner with a password chosen by the installer; there is no default credential. Setup runs in `BEGIN IMMEDIATE` and fails once any user exists                                                                                                                                                                                                                                   | Directive 1. Concurrency-tested (5 parallel attempts -> exactly 1 owner).                                                                                                                                                                          |
| D16 | Argon2id (19 MiB, t=2, p=1, 16-byte random salt), PHC string storage. Password policy: >= 10 chars, not common, not containing username, not single repeated char, not digits only                                                                                                                                                                                                                          | OWASP parameters. Admin-created and admin-reset accounts must change the password at first sign-in; until then every permission check fails closed.                                                                                                |
| D17 | Lockout: 5 consecutive failures lock the account 15 min; login errors never say which part was wrong; unknown users pay the same hashing cost                                                                                                                                                                                                                                                               | Anti brute-force and anti-enumeration. All attempts audited.                                                                                                                                                                                       |
| D18 | Sessions: random 256-bit token, SHA-256 of it kept in memory only, 30 min idle / 12 h absolute. The token is held in Rust (`AppState`); the webview never sees it                                                                                                                                                                                                                                           | A compromised web view cannot steal a session. Single-PC app, so in-memory sessions are sufficient; restart = sign in again.                                                                                                                       |
| D19 | Permissions are reloaded from the DB on every request (no cached grants)                                                                                                                                                                                                                                                                                                                                    | Role changes and deactivation take effect immediately. Authorization is enforced in `singerpro-core` services; the UI only hides what it cannot use.                                                                                               |
| D20 | Privilege-escalation rules: only an Owner may grant/modify Owner; others may only grant permissions they hold; the Owner role is immutable; at least one active Owner must always remain; no self-deactivation                                                                                                                                                                                              | Prevents a `users.manage` holder from taking over the system.                                                                                                                                                                                      |
| D21 | Settings are a closed, typed catalogue (unknown keys rejected, atomic updates, before/after audit). Tax keys need `tax.manage`. Rates entered as percent, stored as basis points                                                                                                                                                                                                                            | Directive 6. Tax/markup defaults remain 0 / disabled.                                                                                                                                                                                              |
| D22 | Logo stored in `binary_assets` (included in backups); only PNG/JPEG accepted, type sniffed from bytes, max 512 KB                                                                                                                                                                                                                                                                                           | No filesystem permission needed; SVG rejected (script risk).                                                                                                                                                                                       |
| D23 | Backup = SQLite `VACUUM INTO` (consistent while running) to a `.partial` file, verified (integrity + FK + schema) then renamed, with a SHA-256 `.manifest.json` sidecar. Existing files are never overwritten                                                                                                                                                                                               | `.spbak` extension.                                                                                                                                                                                                                                |
| D24 | Restore is STAGED while running (verify, safety copy of live DB, byte-checked staged copy) and APPLIED at next startup before the DB is opened. The replaced DB is kept in `replaced/<timestamp>/`; a failed apply puts the original back                                                                                                                                                                   | Avoids Windows file locks and half-overwritten databases. Nothing is deleted automatically.                                                                                                                                                        |
| D25 | Backups from a newer schema than the app are refused; older ones are accepted and migrated on open                                                                                                                                                                                                                                                                                                          | Forward-compatibility safety.                                                                                                                                                                                                                      |
| D26 | Language toggle EN/বাংলা (stored locally and as `ui.language`); Bangla body = Hind Siliguri, formal headings = Tiro Bangla, ৳ falls back to Hind Siliguri inside the Montserrat stack                                                                                                                                                                                                                       | Verified by `scripts/font-check.mjs`.                                                                                                                                                                                                              |
| D27 | `tauri-plugin-dialog` with `dialog:allow-open` only, used for choosing backup folder/file. No fs plugin                                                                                                                                                                                                                                                                                                     | Least privilege.                                                                                                                                                                                                                                   |
| D28 | Stock = immutable `stock_movements` (qty + cost, signed) with cached `stock_balances` (qty + value) per variant and bucket (available, reserved, damaged, warranty, pending_inspection). `stock::reconcile` proves ledger = cache = serial counts/costs                                                                                                                                                     | Directive: ledger is the source of truth; cache reconciled. Triggers block UPDATE/DELETE on all ledgers.                                                                                                                                           |
| D29 | Serial lifecycle graph is fixed in code (`stock::transition_allowed`) and tested exhaustively. Sold -> available is impossible without passing `returned_pending_inspection`; manual UI transitions exclude sold / pending-inspection / returned-to-supplier                                                                                                                                                | Returned appliances never become sellable without inspection (P5 owns the inspection transition and `returns.approve`).                                                                                                                            |
| D30 | Valuation = weighted average cost per variant; serial units carry their own exact cost. Outflow of the whole bucket removes its whole value (no rounding residue)                                                                                                                                                                                                                                           | Cost-of-goods in P3 will use these costs.                                                                                                                                                                                                          |
| D31 | Purchase flow: draft -> confirmed (supplier payable booked, costs allocated, immutable) -> received in one or more receipts. Payable = subtotal - discount; landed costs and discount are allocated by line value into inventory cost; landed costs are NOT added to the supplier payable                                                                                                                   | Freight is normally paid to a transporter, not the supplier. P3 accounting will credit cash/payable for landed costs per posting rules. Each unit cost is a deterministic slice of its line (remainder on last unit) so costs add up to the paisa. |
| D32 | Duplicate supplier invoice numbers are blocked per supplier (case-insensitive) except cancelled purchases                                                                                                                                                                                                                                                                                                   | Prevents double entry of the same invoice.                                                                                                                                                                                                         |
| D33 | Supplier payments carry a per-form idempotency key (`client_key`); re-submits return the original payment. Overpaying a purchase is refused; reversals are new negative rows linked to the original (once only)                                                                                                                                                                                             | Prevents double posting from double clicks.                                                                                                                                                                                                        |
| D34 | Return to supplier credits units x original unit cost; stock leaves at serial cost / average cost; landed costs are not refunded (difference becomes a P&L item when accounting posts in P3)                                                                                                                                                                                                                | Documented simplification; supplier credit is auditable.                                                                                                                                                                                           |
| D35 | Purchases, supplier ledger and stock movements recorded in P2 will get journal entries from the P3 accounting posting engine, keyed by (document type, id) and idempotent                                                                                                                                                                                                                                   | P3 includes a one-time backfill so no P2 document is left unposted.                                                                                                                                                                                |
| D36 | New permissions introduced in a release are granted to default roles once (`default_grants`); an administrator's removals are never undone by later syncs                                                                                                                                                                                                                                                   | Safe upgrades of role configuration.                                                                                                                                                                                                               |
| D37 | Accounting: chart seeded by code; one idempotent journal per document keyed `posting_key`; builders read the document and are used both inline (same transaction) and by `ensure_posted` (start-up back-fill and repair). Full table in docs/ACCOUNTING_POLICY.md                                                                                                                                           | Directive: balanced, immutable, no duplicate posting, reconciliation tools.                                                                                                                                                                        |
| D38 | Revenue booked at sale net of discount; tax to 2200; COGS from the stock ledger cost; receipts settle 1100. Retail must be paid in full; credit only for wholesale/installment customers                                                                                                                                                                                                                    | Simple, auditable; installment markup recognition added in P4.                                                                                                                                                                                     |
| D39 | Customer credit limits are enforced (setting `sales.credit_limit_enforced`, default on); exceeding needs `sales.credit_override`; changing a limit also needs it; both audited                                                                                                                                                                                                                              | Directive: credit limit or manager override.                                                                                                                                                                                                       |
| D40 | Customer payments are allocated to the named invoice or oldest-first and recorded as one receipt per invoice; over-collection is refused (no unapplied advances yet); reversals are new negative receipts needing `customers.reverse_payment`                                                                                                                                                               | Transparent, deterministic allocation.                                                                                                                                                                                                             |
| D41 | Sales and customer payments carry a per-form idempotency key; sale creation runs in `BEGIN IMMEDIATE` so concurrent duplicates return the original                                                                                                                                                                                                                                                          | Duplicate-submit safety, tested with 8 concurrent submissions.                                                                                                                                                                                     |
| D42 | Cart totals shown at the POS come from `sale_preview`, which runs the same pricing code as `create_sale` (price tier, discount, tax)                                                                                                                                                                                                                                                                        | What the cashier sees is what is posted.                                                                                                                                                                                                           |
| D43 | National ID is off by default (`customers.collect_nid`); never returned to roles without `customers.manage`                                                                                                                                                                                                                                                                                                 | Directive: collect only necessary personal data.                                                                                                                                                                                                   |
| D44 | Printing uses the system print dialog from a print-only DOM portal (A4 invoice, 80mm receipt), bundled fonts, no network                                                                                                                                                                                                                                                                                    | Windows print check is a P7 release item.                                                                                                                                                                                                          |
| D45 | Wholesale price precedence: customer-specific price > tier adjustment (% of the wholesale price, -50..+50%) > list wholesale price. Tiers and special prices need `customers.manage_pricing`; every change is audited                                                                                                                                                                                       | Directive: price tiers, customer-specific pricing.                                                                                                                                                                                                 |
| D46 | Installment disclosure: cash price (retail list), installment price (variant installment price, else retail), down payment, principal, markup (default 0%), explicit fees, total payable are stored and shown separately. A markup other than the shop default and any fee need `installments.set_markup`; both are audited                                                                                 | Directive: no hidden interest or fees.                                                                                                                                                                                                             |
| D47 | Schedule: weekly (+7 days), monthly (same day each month, clamped at month end, no drift) or custom dates; the rounding remainder always lands on the final installment; max 120 installments; custom schedules must sum exactly                                                                                                                                                                            | Tested for exact reconciliation over thousands of amounts/counts.                                                                                                                                                                                  |
| D48 | Collections: allocated to the chosen installment first, then oldest-first; partial and advance payments allowed; over-collection refused; one receipt per collection; idempotent per form key. Status (pending/partial/overdue/paid) is derived from allocations and due dates, never stored                                                                                                                | A partial payment can never mark a due as paid.                                                                                                                                                                                                    |
| D49 | Accounting for installments: down payment is a normal receipt; Dr 1110 Installment Receivable (principal+markup+fees) / Cr 1100 (principal) / Cr 2100 Unearned Markup. Collections: Dr cash Cr 1110. Markup recognition is a setting: `proportional_to_collections` (default; income = round(U x collected / total payable), the remainder on the final payment so income totals exactly) or `on_agreement` | Directive: never treat the contract as cash; configurable recognition that cannot over-recognise.                                                                                                                                                  |
| D50 | Early settlement pays the exact outstanding balance minus an optional authorised rebate (needs `installments.reschedule` + reason; limited to unearned markup/fees); the agreement completes only at exactly zero. Reversals of a payment reopen the agreement and roll markup income back                                                                                                                  | Directive: close only after exact settlement or authorised adjustment.                                                                                                                                                                             |
| D51 | Rescheduling supersedes every unpaid schedule row (a superseded row obliges only what was already paid) and creates new rows for the outstanding balance; payments made before a reschedule can no longer be reversed (an adjustment is needed). Needs `installments.reschedule` + reason; audited                                                                                                          | Keeps payment history immutable and schedule totals exact (checked by `schedule_mismatches`).                                                                                                                                                      |
| D52 | Late fees exist only if enabled in Settings (rate and grace days); charged explicitly per overdue installment, once, by an authorised user with a reason; booked to Other Income and shown on the contract                                                                                                                                                                                                  | Directive: late fee only if configured.                                                                                                                                                                                                            |
| D53 | The generic customer-payment screen never applies money to installment invoices; their dues are collected on the agreement. The down payment cannot be reversed on its own                                                                                                                                                                                                                                  | Prevents split, inconsistent allocation.                                                                                                                                                                                                           |
